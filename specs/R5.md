# Especificación R5 — Aplicación demostrativa

Aplicación web para mostrar en la sustentación lo que hacen R2, R3 y R4 con la red vial real,
y las tablas y gráficas de R1 a R4.

- **Backend**: `api/main.py`, FastAPI + uvicorn, en Python. Solo **usa** los módulos del
  proyecto (`quindio.red`, `quindio.dijkstra`, `quindio.envolvente`, `quindio.tsp`); no
  reimplementa ningún algoritmo.
- **Frontend**: `web/`, Vite + React + TypeScript + Tailwind CSS v4. Mapa con react-leaflet,
  gráficas con Recharts. Diseño documentado en `web/DESIGN.md`.
- Un solo proceso: `uvicorn api.main:app --port 8000` sirve la API, las figuras y, si existe
  `web/dist`, la aplicación compilada en `/`.

## 1. Datos cargados UNA vez al iniciar

| Dato | Fuente | Forma en memoria |
|---|---|---|
| Grafo (componente fuertemente conexa) | `red.cargar_grafo()` (nodos.csv, aristas.csv) | `adj[u] = [(v, tiempo_s, distancia_m)]`, `coords[u] = (lat, lon)` |
| Lugares | `data/processed/lugares_nodos.csv` | lista de dicts con id, nombre, categoría, municipio, lat, lon, nodo, duración |
| Matriz de tiempos | `tsp.leer_matriz()` (resultados/matriz_tiempos.csv) | `matriz[a][b]` en segundos |
| Puntos UTM de los nodos | nodos.csv (x_utm, y_utm) | lista de (x, y) enteros (`envolvente.preparar_puntos`) |

## 2. Endpoints

### `GET /api/lugares`
Lista de los 46 lugares: `id, nombre, categoria, municipio, lat, lon, nodo, dist_nodo_m,
duracion_visita_min` (None si no tiene).

### `GET /api/ruta?origen=ID&destino=ID`
Dijkstra con cola de prioridad (`dijkstra.dijkstra_cola`) entre los nodos asociados a los dos
lugares, **calculado en el momento**.
Respuesta: `origen, destino` (id + nombre), `tiempo_s`, `tiempo_min`, `distancia_km` (suma de
`distancia_m` de las aristas de la ruta), `nodos_explorados`, `nodos_ruta`, `ms` (solo el
algoritmo, medido con `time.perf_counter`), `polilinea = [[lat, lon], ...]`.
- Id desconocido → 404.
- `origen == destino` → tiempo 0, distancia 0, polilínea de un punto.

### `GET /api/arbol?origen=ID&destino=ID`
Árbol de exploración de Dijkstra para la misma consulta: `dijkstra_cola(..., arbol=lista)` anota,
en el orden en que cada nodo sale de la cola, `(predecesor, nodo, distancia_definitiva)`.
Respuesta: `tramos` (un tramo predecesor → nodo por cada nodo explorado excepto el origen, con la
forma real de la vía), `tiempos_s` (distancia definitiva del nodo de cada tramo, no decreciente),
`tiempo_s`, `nodos_explorados`, `nodos_grafo` y `ruta`. La vista Ruta lo anima (reproducir,
pausar, barra de pasos, velocidad) para mostrar cómo crece la búsqueda hasta fijar el destino.

### `GET /api/envolvente`
QuickHull propio (`envolvente.quickhull`) sobre los nodos en UTM, calculado en el momento.
Respuesta: `vertices = [{lat, lon, x_utm, y_utm}]` (antihorario), `n_vertices`, `n_puntos`,
`area_km2` (`envolvente.area_km2`), `ms`.

### `POST /api/itinerario`
Cuerpo: `{"partida": "ARM", "atractivos": ["MOQ", ...]}`.
Validación (→ **422** con mensaje en español):
- entre **6 y 8** atractivos, sin repetidos;
- cada id existe y tiene `duracion_visita_min`;
- la partida existe y no está entre los atractivos.

Cálculo en el momento con la matriz de R2 (`tsp.submatriz`):
- Held-Karp (`tsp.held_karp`) y vecino más cercano (`tsp.vecino_mas_cercano`), cada uno con su `ms`.
- Para cada uno: `orden` (ids, empieza y termina en la partida), `filas` con el formato del anexo
  (`orden, lugar, nombre, desplazamiento_desde_anterior_min, visita_min, tiempo_acumulado_h`;
  la última fila es "Regreso"), `total_desplazamientos_min`, `total_visitas_min`, `jornada_h`,
  `cabe` (jornada ≤ 11 h), `tramos = [{desde, hasta, tiempo_min, polilinea}]`.
  Cada polilínea es la ruta de Dijkstra (cola de prioridad) entre los nodos de dos lugares
  consecutivos; las rutas de un mismo par se guardan en un diccionario para no repetirlas.
- `diferencia_min` = desplazamientos voraz − desplazamientos Held-Karp (≥ 0) y
  `diferencia_pct` respecto a Held-Karp.
- La tabla de Held-Karp debe coincidir con `tsp.itinerario()`.

### `GET /api/resultados`
`tablas`: cada CSV de `resultados/` (excepto `matriz_tiempos.csv`, que es una matriz 46×46)
como `{archivo, requerimiento, titulo, columnas, filas}`; los números se devuelven como números.
`requerimiento` sale del prefijo del archivo (`r1_` → "R1", …; `catalogo_` → "Catálogo").
`figuras`: cada PNG de `resultados/figuras/` como `{archivo, requerimiento, url}`.

### Estáticos
- `/figuras/*` → `resultados/figuras/`.
- `/` → `web/dist/index.html` y sus archivos, solo si existe `web/dist`.

## 3. Frontend (vistas)

1. **Ruta**: dos selectores con búsqueda (origen y destino); al calcular, la ruta en el mapa y
   tiempo de viaje, distancia, nodos explorados y ms.
2. **Envolvente**: el polígono sobre el mapa del departamento y los lugares coloreados por
   categoría (con leyenda que no depende solo del color: texto con el nombre de la categoría).
3. **Itinerario**: partida (por defecto ARM) y de 6 a 8 atractivos con validación visible
   (contador y mensaje); resultado de Held-Karp y voraz lado a lado: total, diferencia, tabla de
   orden con tiempo acumulado, si cabe en 11 h, barra de la jornada contra el límite de 11 h, y los
   dos recorridos en el mapa con colores y trazos distintos.
4. **Resultados**: tablas y gráficas de R1 a R4 agrupadas por requerimiento, a partir de
   `/api/resultados`, más las figuras PNG del documento técnico.

## 4. Cómo correrla

```bash
# una vez: dependencias del frontend y compilación
cd web && npm install && npm run build && cd ..
# la app completa en http://localhost:8000
.venv/Scripts/python.exe -m uvicorn api.main:app --port 8000
# desarrollo del frontend con recarga en vivo (deja uvicorn corriendo): http://localhost:5173
cd web && npm run dev
```

O con Docker: `docker build -t rutas-quindio . && docker run -p 8000:8000 rutas-quindio`
(necesita `data/processed/` y `resultados/` ya generados).

## 5. Casos de prueba (`tests/test_api.py`, con `fastapi.testclient`)

1. `GET /api/lugares` → 200, 46 lugares, ARM presente.
2. `GET /api/ruta?origen=ARM&destino=SAL` → 200; `tiempo_s` y `nodos_explorados` iguales a
   `dijkstra_cola(adj, nodo_ARM, nodo_SAL)`; la polilínea empieza en el nodo de ARM y termina en
   el de SAL; `tiempo_s` coincide con la matriz de R2 (±0,01 s); distancia > 0.
3. `GET /api/ruta` con id inexistente → 404.
4. `GET /api/envolvente` → 200; mismo número de vértices y área que `resultados/envolvente.json`.
5. `POST /api/itinerario` con 5 atractivos → 422; con 9 → 422; con un id sin duración → 422.
6. `POST /api/itinerario` con 7 atractivos → 200; total Held-Karp ≤ total voraz; la tabla de
   Held-Karp coincide con `tsp.itinerario()`; cada recorrido visita cada atractivo una vez.
7. `GET /api/resultados` → 200, hay tablas de R1, R2, R3 y R4 y al menos una figura;
   `GET /figuras/<una figura>` → 200.
