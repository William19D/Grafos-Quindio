# Especificación R4 — Ruta óptima de recorrido (TSP asimétrico)

Entradas:
- `resultados/matriz_tiempos.csv` (R2): tiempos mínimos en segundos entre los 46 lugares del
  catálogo; fila = origen, columna = destino. Es **asimétrica** (d(i,j) puede ser distinto de d(j,i)).
- `data/catalogo.csv`: `id`, `categoria`, `duracion_visita_min` (solo los atractivos la tienen).
  Armenia = `ARM`.

Problema: salir de un lugar de partida, visitar k lugares más (cada uno una sola vez) y regresar
al punto de partida minimizando el tiempo total de desplazamiento.

## 1. Representación común (`src/quindio/tsp.py`)

- Los algoritmos reciben una matriz cuadrada `d` (lista de listas) de tamaño (k+1)×(k+1).
  El índice 0 es el lugar de partida; 1..k son los lugares a visitar.
- Un **recorrido** es una lista que empieza y termina en 0 y contiene cada índice 1..k
  exactamente una vez: `[0, a1, a2, ..., ak, 0]`.
- Todos devuelven `(costo, recorrido)` con `costo = suma de d[recorrido[t]][recorrido[t+1]]`.
- Parámetro opcional `traza=None`: si es una lista, se le agregan textos con cada paso. Las
  mediciones se hacen con `traza=None`.
- Casos borde: k = 0 → `(0, [0, 0])`; k = 1 → `(d[0][1] + d[1][0], [0, 1, 0])`.

Funciones:

| Función | Qué hace | Complejidad |
|---|---|---|
| `leer_matriz(ruta)` | lee el CSV → `(ids, matriz)` con `matriz[a][b]` en segundos | O(n²) |
| `leer_catalogo(ruta)` | lee el catálogo → `{id: {"categoria", "nombre", "duracion_min"}}` | O(n) |
| `submatriz(matriz, lugares)` | arma `d` (lista de listas) con `lugares[0]` como partida | O(k²) |
| `costo_recorrido(d, recorrido)` | suma los tramos | O(k) |
| `permutaciones_heap(elementos)` | generador propio (algoritmo de Heap, iterativo) de las k! permutaciones | O(k!) |
| `fuerza_bruta(d, traza)` | prueba las k! permutaciones de 1..k | O(k·k!) tiempo, O(k) memoria |
| `held_karp(d, traza)` | programación dinámica sobre subconjuntos (máscaras de bits); devuelve también el recorrido | O(k²·2^k) tiempo, O(k·2^k) memoria |
| `vecino_mas_cercano(d, traza)` | heurística voraz: siempre al lugar no visitado más cercano y al final regresa | O(k²) tiempo, O(k) memoria |
| `itinerario(partida, atractivos, matriz, duraciones)` | ordena con Held-Karp y arma la tabla del día | O(k²·2^k) |
| `ajustar_a_jornada(partida, atractivos, matriz, duraciones, limite_h=11, traza)` | si no cabe, quita atractivos (criterio abajo) y recalcula | O(k)·O(k·k²·2^k) |

`permutaciones_heap` entrega **la misma lista** modificada en cada paso (un intercambio por
permutación); quien la use debe copiarla si la quiere guardar.

### Recurrencia de Held-Karp

N = {1..k}. C(S, j) = costo mínimo de salir de 0, visitar exactamente los lugares de S
(S ⊆ N, j ∈ S) y terminar en j.

- Caso base: C({j}, j) = d(0, j).
- Recurrencia: C(S, j) = min_{i ∈ S \ {j}} [ C(S \ {j}, i) + d(i, j) ].
- Respuesta: min_{j ∈ N} [ C(N, j) + d(j, 0) ].

La tabla se guarda como listas indexadas por máscara: `C[mascara][j-1]`, donde el bit j-1 de
`mascara` indica si el lugar j está en S. Se llena en orden creciente de máscara (un
subconjunto siempre tiene máscara menor que la del conjunto que lo contiene). Una tabla
paralela `padre[mascara][j-1]` guarda el i que dio el mínimo para reconstruir el recorrido.

### Itinerario

- `duraciones[id]` en minutos; el lugar de partida no tiene visita.
- Filas: `orden, lugar, desplazamiento_desde_anterior_min, visita_min, tiempo_acumulado_h`, y una
  fila final `orden = "Regreso"` con el lugar de partida, `visita_min = "—"`.
- `tiempo_acumulado_h` = (desplazamientos + visitas hasta esa fila) / 60.
- Totales: `total_visitas_min`, `total_desplazamientos_min`, `jornada_h`, `cabe` (jornada ≤ límite).
- Criterio para quitar (en `ajustar_a_jornada`): mientras no quepa, se prueba quitar cada
  atractivo, se recalcula el óptimo con Held-Karp y se quita el que **más acorta la jornada**
  (su visita + el desvío que ahorra). Así se quitan los menos posibles. Empate: el primero en la lista.

## 2. Casos de prueba (`tests/test_r4.py`)

1. Matriz asimétrica 4×4 resuelta a mano (`docs/paso_a_paso_R4.md`):
   ```
   d = [[0, 2, 9, 10],
        [1, 0, 6, 4],
        [15, 7, 0, 8],
        [6, 3, 12, 0]]
   ```
   Óptimo 21 con `[0, 2, 3, 1, 0]` (fuerza bruta y Held-Karp). Vecino más cercano: 33 con
   `[0, 1, 3, 2, 0]` (no encuentra el óptimo).
2. `permutaciones_heap` de 5 elementos produce las 120 permutaciones distintas (se compara con
   `itertools.permutations` solo en la prueba).
3. Matrices aleatorias asimétricas (semilla 2026, k = 0..7): Held-Karp == fuerza bruta en costo
   y el recorrido de cada uno es válido y cuesta lo reportado.
4. Vecino más cercano devuelve una permutación válida y su costo ≥ óptimo.
5. Con la matriz real: el itinerario ajustado de `experimentos/r4_itinerario.py` dura ≤ 11 h y
   sus totales coinciden con la suma de las filas.

## 3. Experimentos

- `experimentos/r4_exactos.py`: partida ARM, k = 5..12 lugares al azar del catálogo (todas las
  categorías, sin ARM) con `random.Random(SEMILLA + k)`. Fuerza bruta y Held-Karp con
  `medir_con_limite` (5 min); al primer "no completada" se deja de aumentar k para ese método.
  Se verifica que ambos den el mismo costo. → `resultados/r4_exactos.csv`, `r4_memoria.csv`.
- `experimentos/r4_calidad.py`: k = 5, 8, 10, 12, 5 instancias por k con
  `random.Random(SEMILLA + 100*k + i)`, i = 0..4. Brecha % = (voraz − óptimo)/óptimo × 100.
  → `r4_calidad.csv`, `r4_calidad_detalle.csv`, `r4_voraz_vs_optimo.json`.
- `experimentos/r4_itinerario.py`: ARM + 7 atractivos → `r4_itinerario.csv`, `r4_itinerario.json`.
- `experimentos/r4_figuras.py`: `resultados/figuras/r4_tiempo_vs_k.png` a partir de `r4_exactos.csv`.
